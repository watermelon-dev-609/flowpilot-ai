# 并行开发协作说明

本文件用于多个 AI 或多个开发会话同时参与 FlowPilot AI 时，减少互相覆盖、重复修复和测试结论冲突。

## 当前原则

- 同一时间只允许一个会话修改同一组页面文件。
- 若某个会话正在做“中文化审计”“全局导航”“页面布局”这类横向任务，其他会话不要同时修改 `frontend/app` 下的页面可见文案。
- 若某个会话正在修测试，其他会话不要批量替换测试文本或重写相同测试文件。
- 新功能优先写到独立目录，确认稳定后再接入导航。

## 可以并行的任务

- 编写阶段计划文档。
- 编写验收清单。
- 梳理接口契约。
- 设计纯函数和数据结构草案。
- 新增独立模块的实施计划。
- 做只读代码审查并输出风险清单。

## 暂时不要并行的任务

- 全站可见文案中文化。
- 全局导航调整。
- 公共组件大改。
- 测试文件批量替换。
- 构建配置调整。
- 依赖升级。

## 文件占用建议

| 任务类型 | 建议占用文件 |
|---|---|
| 中文化审计 | `frontend/app/**`、`frontend/__tests__/**` |
| 内容适配计划 | `docs/superpowers/plans/**` |
| 后端接口设计 | `backend/**`、接口文档 |
| 项目进度记录 | `FlowPilot_AI_项目计划.md` |
| UI 参考整理 | `docs/**` 或项目计划文档 |

## 交接格式

每个小阶段结束时，至少记录：

- 本阶段目标
- 修改文件
- 验证命令
- 验证结果
- 未完成问题
- 下一步建议
- 潜在风险点

## 冲突处理

如果发现另一个会话正在修改同一文件：

1. 停止继续编辑该文件。
2. 只读查看当前差异。
3. 将自己的想法整理为文档或评论。
4. 等对方完成验证后再继续。

## 备注

当前项目目标是形成可展示、可验证、可写进简历的企业智能运营系统。页面本身不展示“简历能力映射”，只通过业务闭环自然体现能力。
