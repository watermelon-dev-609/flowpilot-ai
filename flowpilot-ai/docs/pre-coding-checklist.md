# 编码前检查清单

本清单用于每次真正开始写代码前。  
目的不是增加形式感，而是避免写着写着变成临时补丁、页面堆逻辑、接口不稳定、测试难补。

## 1. 任务边界

- [ ] 当前任务属于哪个阶段，例如 P5.0、P5.1。
- [ ] 本次只解决一个明确问题。
- [ ] 已确认不会和其他会话修改同一批文件。
- [ ] 已确认哪些文件允许修改，哪些文件暂时不要碰。
- [ ] 已确认本阶段不做的内容，避免范围膨胀。

## 2. 接口契约

- [ ] 先定义输入类型。
- [ ] 先定义输出类型。
- [ ] 先定义错误码或错误提示。
- [ ] 前端和后端字段命名一致。
- [ ] 必填字段和可选字段明确。
- [ ] 空值、异常值、边界值的处理明确。

## 3. 分层设计

- [ ] 页面组件只负责渲染和交互。
- [ ] 业务逻辑放到独立函数或服务层。
- [ ] 接口调用与 UI 渲染分离。
- [ ] 纯函数优先，方便测试。
- [ ] 不把 Prompt、规则、平台配置散落在页面代码里。

## 4. 前端状态

- [ ] 有初始空状态。
- [ ] 有加载状态。
- [ ] 有错误状态。
- [ ] 有成功状态。
- [ ] 表单提交时按钮会禁用，避免重复提交。
- [ ] 表单有必填校验。
- [ ] 弹窗或浮层支持 ESC 关闭。
- [ ] 移动端不会横向滚动。

## 5. 安全要求

- [ ] 不在前端硬编码密钥。
- [ ] 不把账号、Cookie、Token 写入仓库。
- [ ] 所有外部输入都要校验。
- [ ] 后端接口必须做真实权限校验，不能只靠前端隐藏按钮。
- [ ] 文本展示要考虑 XSS 风险。
- [ ] 日志不能输出敏感信息。

## 6. 后端要求

- [ ] 参数化查询，避免注入。
- [ ] 写操作考虑幂等。
- [ ] 多步骤写入考虑事务回滚。
- [ ] 并发修改考虑竞态。
- [ ] 资源使用后释放。
- [ ] 统一错误码。
- [ ] 错误响应结构统一。

## 7. 测试要求

- [ ] 先写失败测试。
- [ ] 至少覆盖正常场景。
- [ ] 至少覆盖必填缺失场景。
- [ ] 至少覆盖边界场景。
- [ ] 至少覆盖异常场景。
- [ ] 测试断言用户可见行为，不只测实现细节。
- [ ] 测试文案与页面文案保持一致。

## 8. 验证要求

- [ ] 跑本任务相关测试。
- [ ] 跑完整前端测试。
- [ ] 跑构建。
- [ ] 能打开对应页面。
- [ ] 按验收清单逐项确认。
- [ ] 未通过项记录原因和修复计划。

## 9. 文档记录

- [ ] 修改了什么文件。
- [ ] 实现了什么能力。
- [ ] 运行了什么验证命令。
- [ ] 验证结果是什么。
- [ ] 还有什么风险。
- [ ] 下一步做什么。

## 10. 禁止事项

- [ ] 禁止没有测试就改核心逻辑。
- [ ] 禁止为了方便把业务逻辑塞进页面组件。
- [ ] 禁止用假数据冒充真实结果。
- [ ] 禁止承诺排名、收录或模型引用。
- [ ] 禁止把简历能力映射展示在产品页面。
- [ ] 禁止在不确认编码的情况下直接批量替换中文文档。
