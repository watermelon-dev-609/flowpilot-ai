# P5 母稿生成与多平台内容适配验收清单

本清单用于验收 P5 阶段，不用于约束当前中文化审计收尾任务。  
P5 的目标是先完成“研究选题到多平台草稿”的最小闭环，不做自动发布，不承诺排名、收录或模型引用。

## 1. 项目背景

- [ ] 页面定位为企业内容适配工作台，不展示个人简历能力映射。
- [ ] 功能服务于企业运营人员，把同一份真实业务资料改写成不同平台草稿。
- [ ] 页面明确提示：平台草稿需要人工复核后才能发布。
- [ ] 页面明确提示：系统不承诺搜索排名、平台收录或模型引用。

## 2. 核心流程

- [ ] 用户可以输入品牌名称、产品名称、目标地域、选题标题、目标受众和可确认事实。
- [ ] 用户可以选择至少一个发布平台。
- [ ] 点击生成后，系统能生成一份母稿或内部草稿依据。
- [ ] 系统能生成多个平台版本，至少覆盖微信公众号、知乎、小红书、百家号。
- [ ] 不同平台版本不能只是改格式，必须在标题、结构、语气或内容重点上有差异。
- [ ] 用户可以复制全部草稿。
- [ ] 用户可以下载草稿文本。

## 3. 具体架构

- [ ] 内容生成规则与页面渲染分离。
- [ ] 平台草稿生成逻辑放在独立纯函数文件。
- [ ] 页面组件只负责输入、状态、预览和操作反馈。
- [ ] 平台标识使用稳定枚举，不在页面里散落魔法字符串。
- [ ] 质量评分由独立函数返回，便于后续替换为后端评分或模型评分。

## 4. 平台适配验收

- [ ] 微信公众号版本偏长文解析和专业表达。
- [ ] 知乎版本偏问答结构和判断逻辑。
- [ ] 小红书版本偏场景表达、短段落和弱广告感。
- [ ] 百家号版本偏搜索科普和信息密度。
- [ ] 企业官网版本偏产品介绍、能力说明和案例入口。

## 5. 质量检查

- [ ] 每个平台草稿显示综合评分。
- [ ] 每个平台草稿显示平台适配说明。
- [ ] 每个平台草稿显示推荐标签。
- [ ] 草稿中不得出现“第一”“唯一”“保证排名”等无法验证或绝对化表达。
- [ ] 缺少事实依据时，系统提示用户补充资料，而不是编造参数、案例或数据。

## 6. 异常情况

- [ ] 品牌名称为空时禁止生成，并显示错误提示。
- [ ] 产品名称为空时禁止生成，并显示错误提示。
- [ ] 目标地域为空时禁止生成，并显示错误提示。
- [ ] 选题标题为空时禁止生成，并显示错误提示。
- [ ] 未选择平台时禁止生成，并显示错误提示。
- [ ] 复制失败时显示可理解的错误提示。
- [ ] 下载失败时页面不崩溃，并提示用户重试。

## 7. 状态设计

- [ ] 初始状态显示“暂无平台草稿”。
- [ ] 生成中按钮进入禁用状态，避免重复提交。
- [ ] 生成失败显示错误状态，不保留半成品假结果。
- [ ] 生成成功显示平台草稿卡片。
- [ ] 没有选择平台时显示空状态或校验提示。

## 8. 终端适配

- [ ] 桌面端 1440px 下表单和草稿卡片布局清晰。
- [ ] 笔记本 1024px 下不出现横向滚动。
- [ ] 平板 768px 下卡片自动换行。
- [ ] 手机 375px 下表单和草稿卡片纵向排列。
- [ ] 移动端核心内容可浏览，核心操作可点击。

## 9. 验证命令

```powershell
npm.cmd run test -- --run __tests__/p5-content-adaptation-engine.test.ts __tests__/p5-content-adaptation-page.test.tsx
npm.cmd run test -- --run
npm.cmd run build
```

## 10. 人工验收路径

- [ ] 打开 `/content-adaptation`。
- [ ] 输入一组真实业务资料。
- [ ] 勾选微信公众号、知乎、小红书、百家号。
- [ ] 点击生成平台草稿。
- [ ] 检查各平台标题是否明显不同。
- [ ] 检查各平台结构是否明显不同。
- [ ] 检查是否有“不承诺排名、收录或引用”的边界提示。
- [ ] 点击复制全部草稿。
- [ ] 点击下载草稿文本。

## 11. 本阶段不做

- [ ] 不做自动发布。
- [ ] 不做账号授权。
- [ ] 不保存平台 Cookie。
- [ ] 不接浏览器自动化。
- [ ] 不调用真实模型接口。
- [ ] 不联网抓取平台规则。
- [ ] 不承诺任何平台收录、排名或引用结果。
